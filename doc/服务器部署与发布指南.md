## 二、代码更新后如何重新发布

### 一条命令

```bash
ssh root@123.206.121.190
cd /opt/pm
./release.sh
```

就这样。脚本会自动完成全部步骤。

### 脚本做了什么

| 步骤 | 内容 |
|---|---|
| **1/5 拉取代码** | 优先 `git pull`，失败自动回退到 GitHub tarball |
| **2/5 更新依赖** | `pip install -r requirements-prod.txt` |
| **3/5 构建前端** | `pnpm install` + `pnpm build` |
| **4/5 备份+迁移** | 备份数据库 → `alembic upgrade head` |
| **5/5 重启服务** | `systemctl restart pm` + 健康检查 |

### 安全机制

| 机制 | 说明 |
|---|---|
| **代码备份** | 拉代码前备份到 `/opt/pm-backup-时间戳`，保留最近 5 个 |
| **数据库备份** | 迁移前备份到 `/data/pm/backup/pm_before_release_时间戳.db` |
| **失败回滚提示** | 健康检查失败时打印日志和回滚命令 |
| **原子执行** | 任一步失败即中止，不留半成品 |

## 四、代码更新流程（本地 → 服务器）

```
本地开发
   ↓
git commit && git push        （推到 GitHub main 分支）
   ↓
ssh root@123.206.121.190
cd /opt/pm && ./release.sh    （服务器拉取并发布）
```

**服务器不依赖 git clone**。`release.sh` 用 tarball 下载代码，因为这台服务器访问
`github.com:443` 会超时（`codeload.github.com` 正常）。

如果你的仓库改到别的地方，改 `release.sh` 顶部这两行：

```bash
BRANCH="main"
REPO_TARBALL="https://github.com/tanwb0223/pm/archive/refs/heads/${BRANCH}.tar.gz"
```

## 五、Nginx 配置

配置文件：`/etc/nginx/conf.d/pm.conf`

```nginx
upstream pm_backend {
    server 127.0.0.1:8000;
    keepalive 16;
}

server {
    listen 80;
    server_name chemicalagent.site www.chemicalagent.site;

    client_max_body_size 60m;          # 附件上传上限

    # Let's Encrypt 验证路径（保留，便于以后申请证书）
    location ^~ /.well-known/acme-challenge/ {
        root /var/www/html;
        default_type "text/plain";
        try_files $uri =404;
    }

    location = /healthz {
        access_log off;
        return 200 "ok\n";
    }

    location / {
        proxy_pass http://pm_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;       # 导出报表可能较慢
        proxy_buffering off;
    }
}
```

修改后：

```bash
nginx -t && systemctl reload nginx
```

## 六、关于 HTTPS

### 当前状态

**HTTP 可用，HTTPS 未配置**：

- http://chemicalagent.site ✅
- https://chemicalagent.site ❌

### 为什么没配

`chemicalagent.site` 接入了**腾讯云 EdgeOne（CDN）**，流量先经过 CDN 再回源到服务器。

尝试用 Let's Encrypt 申请证书，三种方式全部失败：

| 方式 | 结果 |
|---|---|
| `certbot --nginx` | `reader size limit exceeded` |
| `certbot --webroot` | 同上 |
| `certbot --standalone` | 同上 |

原因是 Let's Encrypt 的验证请求被 EdgeOne 拦截，无法到达源站。

### 如何启用 HTTPS

**推荐：在 EdgeOne 控制台开启**（不需要动服务器）

腾讯云控制台 → EdgeOne → `chemicalagent.site` → HTTPS 配置 → 开启 →
选「免费证书」→ EdgeOne 自动签发并托管。

详见 [EdgeOne配置指引](EdgeOne配置指引.md)。

**备选：关掉 CDN 直连源站**

让域名直接解析到 `123.206.121.190`，然后：

```bash
certbot certonly --webroot -w /var/www/html \
  -d chemicalagent.site -d www.chemicalagent.site \
  --non-interactive --agree-tos --register-unsafely-without-email
```

成功后把 nginx 配置改成 443 + HTTP 跳转（`ssh` 进去我可以帮你改）。

## 七、故障排查

### 服务起不来

```bash
systemctl status pm
journalctl -u pm -n 50 --no-pager
tail -50 /data/pm/log/app.err.log
```

常见原因：

| 现象 | 原因 | 解决 |
|---|---|---|
| `address already in use` | 8000 端口被占 | `ss -tlnp \| grep 8000` 找到并杀掉 |
| `Permission denied` | 文件属主不对 | `chown -R pm:pm /opt/pm /data/pm` |
| `no such table` | 数据库未初始化 | `cd /opt/pm/backend && sudo -u pm .venv/bin/python -c "from app.db.session import init_db,init_seed_data;init_db();init_seed_data()"` |
| `python: command not found` | venv 损坏 | 重建：`python3 -m venv .venv && .venv/bin/pip install -r requirements-prod.txt` |

### 域名访问异常

```bash
# 1. 本机测试（绕过 nginx）
curl http://127.0.0.1:8000/api/health

# 2. 经 nginx 测试
curl -H 'Host: chemicalagent.site' http://127.0.0.1/api/health

# 3. 外部测试
curl http://123.206.121.190/api/health

# 4. 域名测试
curl http://chemicalagent.site/api/health
```

哪一步失败就查哪一层：

| 失败位置 | 排查方向 |
|---|---|
| 1 失败 | 应用本身，看 app.err.log |
| 2 失败 | nginx 配置，`nginx -t` 检查 |
| 3 失败 | 安全组/防火墙放通 80 端口 |
| 4 失败 | EdgeOne 回源配置或 DNS |

### alembic 报 "table already exists"

已修复（`alembic_sync.py` 自动写入版本标记）。如果还遇到：

```bash
cd /opt/pm/backend
sudo -u pm env $(grep -v '^#' .env | grep -v '^$' | xargs) .venv/bin/python -m alembic stamp head
```

### 前端打不开（白屏）

```bash
# 检查 dist 是否存在
ls /opt/pm/frontend/dist/index.html

# 重新构建
cd /opt/pm/frontend && pnpm build
```

### 磁盘满了

```bash
df -h
du -sh /data/pm/*

# 清理旧备份
ls -dt /opt/pm-backup-* | tail -n +3 | xargs rm -rf
```

## 八、安全建议

### 已做

- 应用只监听 `127.0.0.1:8000`，公网只能通过 nginx 访问
- `.env` 权限 600，含随机生成的 `SECRET_KEY`（40 位）
- 应用以非 root 用户 `pm` 运行
- systemd 启用 `NoNewPrivileges=true`、`PrivateTmp=true`

### 建议做

**1. 改管理员密码**

```bash
# 登录后在系统设置里改，或用脚本
cd /opt/pm/backend
sudo -u pm env $(grep -v '^#' .env | grep -v '^$' | xargs) \
  .venv/bin/python scripts/seed_admin.py admin '新的强密码'
```

**2. 限制源站访问（可选）**

如果只用 EdgeOne 访问，可限制源站 80 端口只允许 CDN 回源 IP：

```bash
# 查看 EdgeOne 回源 IP 段
# https://cloud.tencent.com/document/product/1552/84323
```

**3. 定期检查日志**

```bash
# 登录失败记录
grep -i 'login.*fail' /data/pm/log/app.log | tail -20
```

**4. 配置 SSH 密钥登录，禁用密码**

```bash
# 本地生成密钥
ssh-keygen -t ed25519
ssh-copy-id root@123.206.121.190

# 服务器上禁用密码
sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh
```
