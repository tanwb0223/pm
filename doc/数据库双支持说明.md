# 数据库双支持说明

系统同时支持 **SQLite** 和 **PostgreSQL**，由配置文件决定用哪个，切换不需要改代码。

---

## 一、如何选择

### 默认：SQLite（推荐给单机部署）

**什么都不用配置**，启动即用：

```bash
cd backend
python -m uvicorn app.main:app --port 8000
```

系统自动：
1. 在 `{数据目录}/pm.db` 创建数据库
2. 建 23 张表
3. 灌入基础数据（7 角色 / 38 权限 / 33 参数 / 9 认证方式）

**优点**：
- 零依赖，不需要装数据库
- 备份就是复制一个文件
- 迁移简单（拷贝整个目录）

**适用规模**：400 教师以内，数据量 100GB 以下

### 可选：PostgreSQL（推荐给多人并发场景）

在 `backend/.env` 中配置：

```ini
PM_DATABASE_URL=postgresql+psycopg://用户名:密码@127.0.0.1:5432/pm_prod
```

然后执行迁移：

```bash
alembic upgrade head
```

**优点**：
- 真正的并发写（SQLite 是库级锁）
- JSONB 支持复杂查询
- 适合 1000+ 用户

## 二、配置方式

### 优先级

```
1. 环境变量 PM_DATABASE_URL
2. backend/.env 文件里的 PM_DATABASE_URL
3. 未配置 → 自动用 SQLite
```

### SQLite 的三种写法

```ini
# 相对路径（相对于 backend 目录）
sqlite:///data/pm.db

# 绝对路径（Windows）
sqlite:///D:/data/pm/pm.db

# 绝对路径（Linux）
sqlite:////data/pm/pm.db
```

> 注意：Linux 绝对路径是 **4 个斜杠**（`sqlite:////`），Windows 是 3 个（`sqlite:///D:/...`）。

### 完整配置示例

**SQLite（默认，可不配）**

```ini
# PM_DATABASE_URL=  留空即可，自动用 {PM_DATA_DIR}/pm.db
PM_DATA_DIR=D:/data/pm
```

**PostgreSQL**

```ini
PM_DATABASE_URL=postgresql+psycopg://pm_app:密码@127.0.0.1:5432/pm_prod
```

## 三、两种数据库的差异

| 项 | SQLite | PostgreSQL |
|---|---|---|
| **主键类型** | `INTEGER` 自增 | `BIGINT IDENTITY` |
| **JSON 字段** | `JSON`（存 TEXT） | `JSONB`（可索引） |
| **并发写** | 库级锁（WAL 模式提升） | 行级锁 |
| **定时任务锁** | 文件锁 | `pg_try_advisory_lock` |
| **模糊搜索** | `LOWER() LIKE` | `ILIKE` |
| **日期运算** | 应用层计算 | SQL INTERVAL |
| **建表方式** | 启动时 `create_all` | Alembic 迁移 |
| **备份** | 复制 `.db` 文件 | `pg_dump` |

### 代码如何屏蔽差异

**1. 类型层**（`app/db/types.py`）

```python
# PG 用 BIGINT + Identity，SQLite 用 INTEGER + 自增
BIGINT_PK = BigInteger().with_variant(Integer, "sqlite")

# PG 用 JSONB，SQLite 用 JSON
JSON_TYPE = JSONB().with_variant(JSON, "sqlite")

# 时区感知时间戳（解决 SQLite 返回 naive datetime 的问题）
class AwareDateTime(TypeDecorator): ...
```

**2. 方言层**（`app/db/dialect.py`）

```python
def ilike(column, keyword):
    if is_postgres():
        return column.ilike(f"%{keyword}%")
    return func.lower(column).like(f"%{keyword.lower()}%")

class DatabaseLock:
    """PG 用 advisory lock，SQLite 用文件锁"""
```

**3. 迁移层**（`alembic/alembic_helpers.py`）

```python
def cmt(table, text):
    """表注释（SQLite 自动跳过）"""
    if not is_postgres():
        return
    op.execute(f"COMMENT ON TABLE {table} IS '{text}'")

def upsert_text(sql_pg):
    """PG 用 ON CONFLICT，SQLite 用 INSERT OR IGNORE"""
```

## 四、SQLite 的性能优化

系统已内置以下优化：

```python
PRAGMA journal_mode=WAL      # 读写并发（默认是 DELETE，写会阻塞读）
PRAGMA synchronous=NORMAL    # 降低 fsync 次数（WAL 下安全）
PRAGMA foreign_keys=ON       # 启用外键约束（默认关闭！）
PRAGMA busy_timeout=30000    # 写锁等待 30 秒，避免立即报错
```

### WAL 模式的效果

| 场景 | 默认模式 | WAL 模式 |
|---|---|---|
| 边写边读 | ❌ 阻塞 | ✅ 并发 |
| 写入速度 | 慢（每次 fsync） | 快 3-5 倍 |
| 崩溃恢复 | 完整 | 完整 |

### 400 教师规模的实测数据

| 指标 | 实测值 | 说明 |
|---|---|---|
| 数据量（3 年） | 100 MB | 含 131,400 条快照 |
| 含索引膨胀 | 200 MB | 远低于 100 GB 上限 |
| 插入速度 | 32 万行/秒 | 批量 |
| 索引查询 | 0.05 ms/次 | 单条 |
| 最坏并发 | 0.11 次写/秒 | 400 人集中填周报 |
| 余量 | **900 倍** | 完全够用 |

## 五、从 SQLite 迁移到 PostgreSQL

如果一开始用 SQLite，后来数据量大了要换 PG：

### 1. 导出 SQLite 数据

```bash
# 用 Python 脚本导出（不能用 pg_dump，格式不同）
python scripts/export_to_sql.py --dialect sqlite --output dump.sql
```

### 2. 建 PostgreSQL 库

```bash
createdb -U postgres pm_prod
```

### 3. 建表结构

```bash
PM_DATABASE_URL=postgresql+psycopg://... alembic upgrade head
```

### 4. 导入数据

```bash
PM_DATABASE_URL=postgresql+psycopg://... python scripts/import_from_sql.py dump.sql
```

### 5. 切换配置

```ini
PM_DATABASE_URL=postgresql+psycopg://...
```

> **建议**：如果预期 2 年内会超过 500 教师，直接上 PostgreSQL 更省事。

## 六、常见问题

### Q1: 启动报「no such table」

SQLite 首次启动应该自动建表。如果没建：

```bash
# 手动执行
python -c "from app.db.session import init_db, init_seed_data; init_db(); init_seed_data()"
```

### Q2: 报「database is locked」

说明有长时间写事务。检查：

1. 是否有大事务未提交（代码里 `db.commit()` 是否漏了）
2. `busy_timeout` 是否生效（默认 30 秒）

如果是定时任务和用户操作冲突，可以把定时任务改到凌晨。

### Q3: SQLite 数据库文件越来越大

WAL 模式会生成 `-wal` 和 `-shm` 文件。正常情况下会自动清理。如果异常增大：

```sql
PRAGMA wal_checkpoint(TRUNCATE);
```

### Q4: 时间字段报时区错误

已通过 `AwareDateTime` 类型解决。如果自己写模型，必须用：

```python
from app.db.types import aware_timestamp

created_at = aware_timestamp(server_default=func.now())
```

不要直接用 `mapped_column(DateTime(timezone=True))`。

### Q5: 从 PG 切回 SQLite 数据会丢吗

会的，两种数据库的数据格式不同，切换需要导出导入。

### Q6: Alembic 在 SQLite 上能跑吗

能。已改造完成，两个数据库都能跑：

```bash
PM_DATABASE_URL=sqlite:///D:/data/pm/pm.db alembic upgrade head
PM_DATABASE_URL=postgresql+psycopg://... alembic upgrade head
```

不过 SQLite 通常不需要，启动时会自动 `create_all`。
