# 线下部署手册（Linux 单机 · SQLite）

> 适用版本：`be78c95` 及以后
> 适用场景：内网/离线服务器，一台机器跑完整系统
> 目标：**解压或拉取代码 → 执行脚本 → 浏览器可用**

---

## 一、方案总览

### 1.1 架构

```
用户浏览器
    │ HTTPS 443 / HTTP 80
    ▼
┌─────────────────────────────────┐
│  Nginx（反向代理 + 静态托管）    │
│  ├── /            → 前端静态文件 │
│  └── /api/        → 127.0.0.1:8000│
└─────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────┐
│  Uvicorn（2 进程）               │
│  FastAPI 应用                    │
│  监听 127.0.0.1:8000             │
└─────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────┐
│  SQLite  /data/pm/pm.db          │
│  附件    /data/pm/upload/        │
│  日志    /data/pm/log/           │
│  备份    /data/pm/backup/        │
└─────────────────────────────────┘
```

**不需要**：PostgreSQL、Docker、Redis、消息队列。

### 1.2 技术栈

| 层 | 技术 | 版本要求 |
|---|---|---|
| 后端 | Python + FastAPI | Python ≥ 3.12 |
| 数据库 | SQLite | 3.35+（需支持 WAL） |
| 前端 | React 18 + Vite | 构建时需 Node.js ≥ 18 |
| Web 服务器 | Nginx | 1.20+ |
| 进程管理 | systemd | 系统自带 |

### 1.3 目录规划

| 路径 | 用途 | 属主 |
|---|---|---|
| `/opt/pm` | 代码 + 虚拟环境 | `pm:pm` |
| `/opt/pm/backend` | 后端代码 + `.venv` | `pm:pm` |
| `/opt/pm/frontend/dist` | 前端构建产物 | `pm:pm` |
| `/data/pm` | 数据根目录 | `pm:pm` |
| `/data/pm/pm.db` | SQLite 数据库 | `pm:pm` |
| `/data/pm/upload` | 附件文件 | `pm:pm` |
| `/data/pm/log` | 运行日志 | `pm:pm` |
| `/data/pm/backup` | 数据库备份 | `pm:pm` |

> **重要**：`/data/pm` 是唯一需要备份的目录。升级代码时**绝不要删除它**。

## 二、服务器准备

### 2.1 硬件建议

| 规模 | CPU | 内存 | 磁盘 |
|---|---|---|---|
| 演示 / 400 教师以内 | 2 核 | 2 GB | 40 GB |
| 400~1000 教师 | 4 核 | 4 GB | 100 GB |
| 附件较多（>10 GB） | 4 核 | 4 GB | 按实际 ×2 |

> 实测：2 核 1.9 GB 跑 400 教师规模，内存占用约 600 MB，余量充足。

### 2.2 操作系统

已验证：**Debian 13 (trixie)**。
兼容：Ubuntu 22.04/24.04、Debian 12、CentOS Stream 9（命令需换成 `dnf`）。

### 2.3 安装系统依赖

```bash
apt-get update
apt-get install -y \
    python3 python3-venv python3-pip \
    nginx \
    sqlite3 \
    git curl wget tar \
    fonts-wqy-zenhei
```

> **字体说明（重要）**：中文 PDF 导出需要 **TrueType 轮廓**的中文字体。
>
> - ✅ `fonts-wqy-zenhei`（文泉驿正黑）—— reportlab 支持
> - ❌ `fonts-noto-cjk` —— 是 PostScript/CFF 轮廓，reportlab 会报
>   `postscript outlines are not supported`
>
> 只装 `fonts-noto-cjk` 会导致导出 PDF 时报 500。必须装文泉驿。

如果服务器**不能联网**，用离线包（见第七章）。

### 2.4 检查 Python 版本

```bash
python3 --version
# 需要 3.12 及以上
```

低于 3.12 需要单独安装（Debian 13 自带 3.13，一般不用管）。

### 2.5 创建运行用户

```bash
# 系统用户，不允许登录
useradd -r -m -d /opt/pm -s /bin/bash pm

# 验证
id pm
```

## 三、部署代码

### 3.1 方式 A：从 Git 拉取（服务器能联网）

```bash
mkdir -p /opt/pm
cd /opt
git clone https://github.com/tanwb0223/pm.git pm
cd /opt/pm
git log --oneline -1        # 确认版本
```

### 3.2 方式 B：本地上传（服务器不能联网）

**在能联网的电脑上**打包：

```bash
# Linux / macOS
cd /path/to/pm
tar --exclude='.git' --exclude='node_modules' --exclude='.venv' \
    --exclude='dist' --exclude='__pycache__' --exclude='data' \
    -czf pm-src.tar.gz .

# Windows PowerShell
tar -czf pm-src.tar.gz --exclude=.git --exclude=node_modules --exclude=.venv `
    --exclude=dist --exclude=__pycache__ --exclude=data .
```

> **注意**：`__init__.py` 千万不能排除，否则 Python 包导入会失败。

上传并解压：

```bash
# 上传
scp pm-src.tar.gz root@服务器IP:/tmp/

# 服务器上解压
mkdir -p /opt/pm
tar xzf /tmp/pm-src.tar.gz -C /opt/pm
```

**校验包完整性**（重要）：

```bash
cd /opt/pm
echo "backend __init__.py 数量: $(find backend/app -name '__init__.py' | wc -l)"
# 应输出 12 或更多，如果是 0 说明打包漏了文件

test -f backend/app/auth/providers/__init__.py && echo "关键文件 OK" || echo "关键文件缺失"
```

### 3.3 调整目录属主

```bash
mkdir -p /data/pm/{upload,log,backup,locks}
chown -R pm:pm /opt/pm /data/pm
chmod 750 /data/pm
```

### 4.1 创建虚拟环境

```bash
cd /opt/pm/backend
python3 -m venv .venv
.venv/bin/pip install --upgrade pip
```

### 4.2 安装依赖

**能联网**：

```bash
.venv/bin/pip install -r requirements-prod.txt
```

**不能联网**（用离线 wheel 包）：

```bash

    -d wheels/ \
    --platform manylinux_2_28_x86_64 \
    --python-version 313 \
    --only-binary=:all:

# 拷到服务器后安装
.venv/bin/pip install --no-index --find-links=wheels/ -r requirements-prod.txt
```

**验证依赖**：

```bash
.venv/bin/python -c "
import fastapi, uvicorn, sqlalchemy, alembic, psycopg, pydantic
import jwt, argon2, ldap3, apscheduler, openpyxl, reportlab, httpx
print('依赖完整')
"
```

### 4.3 生成配置文件

```bash
cd /opt/pm/backend
cat > .env << 'EOF'
# ---------------------------------------------------------------- 应用
PM_APP_NAME=产教融合项目管理系统
PM_DEBUG=false
PM_SECRET_KEY=请替换为随机字符串
PM_ACCESS_TOKEN_EXPIRE_MINUTES=30

# ---------------------------------------------------------------- 数据目录
PM_DATA_DIR=/data/pm
PM_UPLOAD_DIR=/data/pm/upload
PM_BACKUP_DIR=/data/pm/backup
PM_UPLOAD_MAX_SIZE_MB=50

# ---------------------------------------------------------------- 数据库
# 留空 = 自动使用 SQLite（/data/pm/pm.db）
# 用 PostgreSQL 时取消注释并修改：
# PM_DATABASE_URL=postgresql+psycopg://用户:密码@127.0.0.1:5432/pm_prod

# ---------------------------------------------------------------- 前端
# Nginx 托管前端，所以设为 false
PM_FRONTEND_SERVE=false
PM_FRONTEND_DIR=/opt/pm/frontend/dist

# ---------------------------------------------------------------- 定时任务
PM_SCHEDULER_ENABLED=true
PM_DAILY_SCAN_HOUR=1
PM_DIGEST_HOUR=8
PM_DIGEST_MINUTE=30

# ---------------------------------------------------------------- 自动备份
PM_BACKUP_ENABLED=true
PM_BACKUP_HOUR=2
PM_BACKUP_MINUTE=0
PM_BACKUP_KEEP_DAYS=30

# ---------------------------------------------------------------- 邮件（可选）
PM_SMTP_HOST=
PM_SMTP_PORT=465
PM_SMTP_USER=
PM_SMTP_PASSWORD=
PM_SMTP_USE_SSL=true
PM_MAIL_FROM=
EOF

chmod 600 .env
chown pm:pm .env
```

**生成随机 SECRET_KEY**：

```bash
python3 -c "import secrets,string; print(''.join(secrets.choice(string.ascii_letters+string.digits) for _ in range(48)))"
```

把输出填到 `PM_SECRET_KEY=`。

> **SECRET_KEY 必须改**。它用于 JWT 签名，泄露会导致任何人都能伪造登录态。
> 修改后已登录用户需要重新登录。

## 六、配置 Nginx

### 6.1 写入站点配置

**有域名 + 有证书**：

```bash
cat > /etc/nginx/conf.d/pm.conf << 'EOF'
upstream pm_backend {
    server 127.0.0.1:8000;
    keepalive 16;
}

# HTTP 跳转 HTTPS
server {
    listen 80;
    server_name your-domain.com;

    location ^~ /.well-known/acme-challenge/ {
        root /var/www/html;
        default_type "text/plain";
        try_files $uri =404;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    http2 on;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    client_max_body_size 60m;
    root /opt/pm/frontend/dist;
    index index.html;

    gzip on;
    gzip_static on;
    gzip_vary on;
    gzip_comp_level 6;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/json application/javascript
               text/xml application/xml image/svg+xml;

    access_log /var/log/nginx/pm-access.log;
    error_log  /var/log/nginx/pm-error.log warn;

    location /api/ {
        proxy_pass http://pm_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_buffering off;
    }

    location /assets/ {
        expires 30d;
        access_log off;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
EOF
```

**只有 IP、没有域名**（内网环境）：

```bash
cat > /etc/nginx/conf.d/pm.conf << 'EOF'

```

### 6.2 检查并重载


## 七、配置 systemd 服务

### 7.1 写入服务文件

```bash
cat > /etc/systemd/system/pm.service << 'EOF'
[Unit]
Description=产教融合项目管理系统 (PM)
After=network.target

[Service]
Type=simple
User=pm
Group=pm
WorkingDirectory=/opt/pm/backend
EnvironmentFile=/opt/pm/backend/.env
ExecStart=/opt/pm/backend/.venv/bin/uvicorn app.main:app \
    --host 127.0.0.1 --port 8000 \
    --workers 2 --proxy-headers --forwarded-allow-ips=*
Restart=always
RestartSec=5
StandardOutput=append:/data/pm/log/app.log
StandardError=append:/data/pm/log/app.err.log

NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
EOF
```

> `--workers 2` 表示 2 个进程。内存紧张可改 1，CPU 多可调到 `CPU核数`。

### 7.2 启动

```bash
systemctl daemon-reload
systemctl enable pm
systemctl start pm

# 等待几秒
sleep 8

# 检查
systemctl is-active pm
curl -s http://127.0.0.1:8000/api/health
```

期望输出：

```json
{"code":0,"message":"ok","data":{"status":"up","app":"产教融合项目管理系统"}}
```

### 7.3 起不来怎么查

```bash
# 1. 服务状态
systemctl status pm --no-pager -l

# 2. 应用日志（最有用）
tail -50 /data/pm/log/app.err.log

# 3. 端口是否在听
ss -tlnp | grep 8000

# 4. 手动跑一次，看完整报错
cd /opt/pm/backend
sudo -u pm env $(grep -v '^#' .env | grep -v '^$' | xargs) \
    .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

常见错误对照表：

| 报错 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: No module named 'app'` | 工作目录不对 | 确认 `WorkingDirectory=/opt/pm/backend` |
| `ImportError: cannot import name 'xxx' from 'app.xxx' (unknown location)` | 打包漏了 `__init__.py` | 重新打包，确保包含所有 `__init__.py` |
| `Permission denied: /data/pm/pm.db` | 属主不对 | `chown -R pm:pm /data/pm` |
| `address already in use` | 8000 被占用 | `ss -tlnp \| grep 8000` 找到并杀掉 |
| `no such table` | 未初始化数据库 | 执行第四章 4.4 |
| `SECRET_KEY` 相关错误 | `.env` 未加载 | 确认 `EnvironmentFile` 路径正确 |

## 八、HTTPS 配置（有域名时）

### 8.1 申请 Let's Encrypt 证书

```bash
apt-get install -y certbot

# 先停 nginx（用 standalone 方式）
systemctl stop nginx

certbot certonly --standalone \
    -d your-domain.com -d www.your-domain.com \
    --non-interactive --agree-tos --register-unsafely-without-email

systemctl start nginx
```

> **国内服务器注意**：如果域名未备案，Let's Encrypt 验证会被云厂商拦截，报
> `reader size limit exceeded`。这种情况只能用 IP 访问，或改用云厂商的免费证书。

### 8.2 配置自动续期

```bash
# 测试续期（不会真的续）
certbot renew --dry-run
```

certbot 安装时一般会自动创建 timer：

```bash
systemctl list-timers | grep certbot
```

如果没有，手动加：

```bash
cat > /etc/systemd/system/pm-certbot-renew.service << 'EOF'
[Unit]
Description=Renew Let's Encrypt certificate (PM)
After=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/bin/certbot renew --quiet --deploy-hook "systemctl reload nginx"
EOF

cat > /etc/systemd/system/pm-certbot-renew.timer << 'EOF'
[Unit]
Description=Daily renewal check for PM certificate

[Timer]
OnCalendar=*-*-* 03:00:00
RandomizedDelaySec=1800
Persistent=true

[Install]
WantedBy=timers.target
EOF

systemctl daemon-reload
systemctl enable --now pm-certbot-renew.timer
```

> **只有 IP 没有域名时**，无法申请受信任的证书。可以：
> 1. 用 HTTP 访问（内网够用）
> 2. 用自签证书（浏览器会警告）
> 3. 让云厂商签发 IP 证书（部分厂商支持）

## 十、日常运维

### 10.1 服务管理

```bash
systemctl status pm          # 状态
systemctl restart pm         # 重启
systemctl stop pm            # 停止
systemctl start pm           # 启动
```

## 十一、升级部署

### 11.1 一键升级（服务器能访问 Git）

```bash
cd /opt/pm
chmod +x release.sh     # 首次需要赋可执行权限
./release.sh
```

脚本会：

1. 备份代码到 `/opt/pm-backup-时间戳`
2. 拉取最新代码
3. 更新 Python 依赖
4. 构建前端
5. 备份数据库 + 执行迁移
6. 重启服务 + 健康检查

**只改后端时**跳过前端构建，省 20 秒：

```bash
SKIP_FRONTEND=1 ./release.sh
```

### 11.2 手动升级（离线环境）

**步骤 1：本地打包**

```bash
cd /path/to/pm
tar --exclude='.git' --exclude='node_modules' --exclude='.venv' \
    --exclude='dist' --exclude='__pycache__' --exclude='data' \
    -czf pm-update.tar.gz .
```

**步骤 2：备份服务器**

```bash
TS=$(date +%Y%m%d_%H%M%S)
mkdir -p /opt/pm-backup-$TS
cp -a /opt/pm/backend/app /opt/pm-backup-$TS/app
cp -a /opt/pm/backend/alembic /opt/pm-backup-$TS/alembic
cp /data/pm/pm.db /data/pm/backup/pm_before_upgrade_$TS.db
echo "备份完成: /opt/pm-backup-$TS"
```

**步骤 3：上传并替换**

```bash
scp pm-update.tar.gz root@服务器IP:/tmp/

# 服务器上
systemctl stop pm
rm -rf /tmp/pm-new && mkdir -p /tmp/pm-new
tar xzf /tmp/pm-update.tar.gz -C /tmp/pm-new

cd /opt/pm
rm -rf backend/app backend/alembic backend/scripts
cp -a /tmp/pm-new/backend/app backend/app
cp -a /tmp/pm-new/backend/alembic backend/alembic
cp -a /tmp/pm-new/backend/scripts backend/scripts
cp -a /tmp/pm-new/backend/alembic.ini backend/
cp -a /tmp/pm-new/frontend/. frontend/
chown -R pm:pm backend frontend
```

**步骤 4：更新依赖与迁移**

```bash
cd /opt/pm/backend
.venv/bin/pip install -r requirements-prod.txt
sudo -u pm env $(grep -v '^#' .env | grep -v '^$' | xargs) \
    .venv/bin/python -m alembic upgrade head
```

**步骤 5：构建前端**

```bash
cd /opt/pm/frontend
pnpm install --frozen-lockfile
pnpm build
chown -R pm:pm /opt/pm/frontend
```

**步骤 6：启动并验证**

```bash
systemctl start pm
sleep 8
systemctl is-active pm
curl -s http://127.0.0.1:8000/api/health
```

### 11.3 回滚

升级失败时：

```bash
# 1. 停服务
systemctl stop pm

# 2. 回滚代码
cp -a /opt/pm-backup-时间戳/app /opt/pm/backend/app
cp -a /opt/pm-backup-时间戳/alembic /opt/pm/backend/alembic
cp -a /opt/pm-backup-时间戳/scripts /opt/pm/backend/scripts

# 3. 回滚数据库（仅当迁移出问题时）
cp /data/pm/backup/pm_before_upgrade_时间戳.db /data/pm/pm.db
chown pm:pm /data/pm/pm.db

# 4. 启动
systemctl start pm
```

> **注意**：数据库回滚会丢失升级后产生的新数据，只在迁移失败时使用。

## 十二、安全加固

### 12.1 必做项

| 项 | 操作 |
|---|---|
| **改 SECRET_KEY** | `.env` 里换成随机 48 位字符串 |
| **改管理员密码** | 登录后系统设置里改，或 `seed_admin.py` 重置 |
| **限制 SSH** | 改用密钥登录，禁用密码 |
| **配防火墙** | 只放通 22/80/443 |

**防火墙**：

```bash
# 用 ufw（Debian/Ubuntu）
apt-get install -y ufw
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
ufw status
```

> 注意：8000 端口**不要**对外开放，只让 Nginx 走 127.0.0.1 访问。

**SSH 密钥登录**：

```bash
# 本地生成密钥
ssh-keygen -t ed25519

# 上传公钥
ssh-copy-id root@服务器IP

# 服务器上禁用密码登录
sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh
```

### 12.2 建议项

- 定期检查 `/data/pm/log/app.log` 的登录失败记录
- 附件目录设置独立磁盘配额，防止写满系统盘
- 数据库备份定期拷到另一台机器（避免单机故障）
- 关注 `/data/pm` 磁盘使用率

**磁盘监控脚本**（可选）：

```bash
cat > /opt/pm/check-disk.sh << 'EOF'
#!/bin/bash
THRESHOLD=85
USAGE=$(df /data | tail -1 | awk '{print $5}' | tr -d '%')
if [ "$USAGE" -gt "$THRESHOLD" ]; then
    echo "警告：/data 磁盘使用率 ${USAGE}%，超过 ${THRESHOLD}%" | \
        mail -s "PM 服务器磁盘告警" admin@example.com
fi
EOF
chmod +x /opt/pm/check-disk.sh

# 加到 crontab
(crontab -l 2>/dev/null; echo "0 9 * * * /opt/pm/check-disk.sh") | crontab -
```

## 十三、常见问题

### Q1: 页面白屏

```bash
# 1. 检查 dist 是否存在
ls -lh /opt/pm/frontend/dist/index.html

# 2. 检查 Nginx root 路径
grep root /etc/nginx/conf.d/pm.conf

# 3. 检查浏览器控制台报错
# 常见：/assets/xxx.js 404 → dist 没构建或路径不对
```

### Q2: API 全部 502

后端没起来。查：

```bash
systemctl status pm
tail -50 /data/pm/log/app.err.log
ss -tlnp | grep 8000
```

### Q3: 登录后刷新就退出

`SECRET_KEY` 变了，或 Token 过期时间太短。检查 `.env`：

```bash
grep SECRET_KEY /opt/pm/backend/.env
grep ACCESS_TOKEN_EXPIRE /opt/pm/backend/.env
```

### Q4: 导出 PDF 报 500，日志提示找不到中文字体

**原因**：reportlab 只支持 TrueType 轮廓字体。`fonts-noto-cjk` 是 CFF 轮廓，
会报 `postscript outlines are not supported`。

**解决**：

```bash
apt-get install -y fonts-wqy-zenhei
systemctl restart pm
```

验证：

```bash
curl -s -o /tmp/t.pdf -w '%{http_code}' -m 30 \
    -H "Authorization: Bearer $TOKEN" \
    'http://127.0.0.1:8000/api/export/progress?fmt=pdf'
# 应返回 200
file /tmp/t.pdf   # 应为 PDF document
```

如果还是失败，把字体文件直接放到项目目录：

```bash
mkdir -p /opt/pm/backend/fonts
cp /usr/share/fonts/truetype/wqy/wqy-zenhei.ttc /opt/pm/backend/fonts/simhei.ttf
chown -R pm:pm /opt/pm/backend/fonts
systemctl restart pm
```

### Q5: 上传附件失败

```bash
# 检查上传目录权限和空间
ls -ld /data/pm/upload
df -h /data

# 检查 Nginx 大小限制
grep client_max_body_size /etc/nginx/conf.d/pm.conf
```

### Q6: 数据库被锁

```bash
# 查看是否有僵尸进程
ps aux | grep uvicorn

# 检查 WAL 文件
ls -lh /data/pm/pm.db*

# 手动 checkpoint
sqlite3 /data/pm/pm.db "PRAGMA wal_checkpoint(TRUNCATE);"
```

### Q7: 磁盘满了

```bash
df -h
du -sh /data/pm/*
du -sh /data/pm/upload

# 清理旧备份
find /data/pm/backup -name "*.db*" -mtime +30 -delete

# 清理日志
truncate -s 0 /data/pm/log/app.log
truncate -s 0 /data/pm/log/app.err.log
```

### Q8: 想换成 PostgreSQL

编辑 `.env`：

```ini
PM_DATABASE_URL=postgresql+psycopg://pm_app:密码@127.0.0.1:5432/pm_prod
```

然后：

```bash
# 建库
sudo -u postgres psql -c "CREATE DATABASE pm_prod ENCODING 'UTF8';"
sudo -u postgres psql -c "CREATE USER pm_app WITH PASSWORD '密码';"
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE pm_prod TO pm_app;"

# 迁移
cd /opt/pm/backend
sudo -u pm env $(grep -v '^#' .env | grep -v '^$' | xargs) \
    .venv/bin/python -m alembic upgrade head

# 灌基础数据
sudo -u pm env $(grep -v '^#' .env | grep -v '^$' | xargs) \
    .venv/bin/python -c "from app.db.session import init_seed_data; init_seed_data()"

# 重启
systemctl restart pm
```

> SQLite 数据不会自动迁移到 PostgreSQL，需要用脚本导出导入。
> 详见 [数据库双支持说明](数据库双支持说明.md)。
