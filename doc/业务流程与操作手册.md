# 产教融合项目管理系统 —— 完整业务流程与执行步骤

> 本文所有规则均从代码核实（标注了实现位置），不是照需求文档转述。
> 对应代码版本：`a21d721`（2026-10-21）

---

## 零、总览：一条数据链，五个阶段

```
① 基础配置          ② 项目立项            ③ 分解与派工
   组织/人员/角色  →   建大项目、定参与学院  →  建子项目、定负责人/计划/权重
                                                    ↓
⑤ 复盘与结项   ←   ④ 日常运转（进度/报表/预警/风险）
```

**关键约束**：前一阶段数据不齐，后一阶段算不出来。
- 学院没建 → 人员无法归属、项目无法配学院、子项目建不出来
- 子项目没负责人或没计划时间 → 算不出偏差 → 预警引擎空转

## 阶段 ① 基础配置（系统管理员，一次性）

### 执行步骤

| 序 | 操作 | 入口 | 说明 |
|---|---|---|---|
| 1 | 建学院 | 系统管理 → 组织管理 | 支持单个新增或 Excel 批量导入。可设上级组织形成两级 |
| 2 | 建人员 | 系统管理 → 用户管理 → 批量导入 | 模板「学院」列按**已有学院名称或编码**匹配，所以必须第 1 步先做 |
| 3 | 配角色授权 | 系统管理 → 角色权限 → 用户授权 | 选「角色 + 数据范围」 |
| 4 | 调系统参数 | 系统管理 → 参数配置 | 预警阈值、报表时限、通知开关等 33 项 |
| 5 | 设免填日历 | 系统管理 → 免填日历 | 寒暑假/节假日，免填日不计入预警计时 |
| 6 | 配认证方式 | 系统管理 → 认证方式 | 9 种协议，按学校统一身份认证选 |

### 授权模型（这是整套权限的地基）

一个用户可以有多条授权，每条 = **角色 + 数据范围**：

| 数据范围 | 含义 |
|---|---|
| `ALL` | 全校 |
| `MAJOR` | 指定大项目 |
| `COLLEGE` | 指定学院 |
| `SELF` | 本人负责的 |
| `CUSTOM` | 自定义（带有效期） |

> 同一个老师可以在 A 项目里是「学院负责人」、在 B 项目里只是「填报人」，
> 靠 `(role_id, scope_type, scope_id)` 三元组表达。授权可设有效期，到期自动失效。

### 7 个内置角色的权限梯度

| 角色 | 权限数 | 关键能力 |
|---|---|---|
| SYS_ADMIN 系统管理员 | 38 | 全部 |
| PROJECT_OWNER 项目总负责人 | 30 | 除系统管理外全部业务权限，可作废报表 |
| MAJOR_OWNER 大项目负责人 | 28 | 催办、编辑风险、转交预警、编辑项目/子项目 |
| COLLEGE_OWNER 学院负责人 | 23 | 代填进度、关闭预警、管理参与学院 |
| SUB_OWNER 子项目负责人 | 20 | 填进度、填报表、认领预警 |
| REPORTER 填报人 | 19 | 填进度、填报表 |
| VIEWER 只读 | 14 | 仅查看与导出 |

## 阶段 ② 项目立项（项目总负责人）

### 执行步骤

1. **项目管理 → 大项目 → 新建项目**
   - 填：项目名称、类型（产业学院/实训基地/订单班/课程教材/双师基地/其他）、合作企业、建设周期、总负责人、**原始计划起止**
2. **进入项目详情 → 添加参与学院**，并为每个学院指定**学院负责人**
3. **点「完整性检查」**，确认 4 项齐全

### 完整性检查的 4 项（`project_service.check_completeness`）

| 检查项 | 不通过的后果 |
|---|---|
| 是否配置参与学院 | 无法继续分解 |
| 每个学院是否有负责人 | 触发 AL-09 红色预警 |
| 是否有子项目 | 无法计算进度 |
| 每个子项目是否有负责人 | 触发 AL-09 |
| 是否有计划起止时间 | 触发 AL-10，且**算不出时间进度** |

### 关键规则

- **原始计划立项时锁定**，编辑不改（`original_start/original_end` 独立于 `plan_start/plan_end`）
- 后续调整计划走变更，**历史进度记录不重算**，时间进度按新计划即时重算

---

## 阶段 ③ 分解与派工（学院负责人 / 大项目负责人）

### 执行步骤

1. **项目管理 → 子项目 → 新建子项目**
2. 必须同时选定：**大项目 + 该大项目已参与的学院**（后端强校验，否则 400）
3. 填：负责人、计划起止、权重（可空，空则按等权）

### 硬约束

- 子项目 `major_id` 和 `college_id` **均非空**
- 学院必须先参与该项目，才能在其下建子项目
- 每个子项目必须有负责人

## 阶段 ④ 日常运转（全员，这是系统最高频部分）

### 4.1 进度更新 —— 两个入口，同一套规则

| 入口 | 位置 | 适用 |
|---|---|---|
| 子项目行内填报 | 进度总表 → 行内「填报」 | 快速更新 |
| 报表提交时顺带更新 | 报表填报 → 勾选「同步更新进度」 | 填报时一起改 |

### 进度更新的 6 条规则（`progress_service.update_progress`）

| 规则 | 说明 |
|---|---|
| 已结项不能改 | `status=CLOSED` 直接拒绝 |
| 已中止不能改 | 需先重启 |
| 进度 0–100 | 越界报错 |
| **回调必须填原因** | 进度低于上次时强制要求，且记录标记 `is_rollback` |
| **代填留痕** | 操作人 ≠ 负责人时记 `on_behalf_of` |
| **「本周期无变化」** | 勾选后不改进度值，但仍记录一次更新（用于区分「没干活」和「没更新」） |

> 每次改动都写 `prog_record` 留底，可查完整历史。

### 4.2 进度与偏差怎么算

```
时间进度 = (今天 − 计划开始) ÷ (计划结束 − 计划开始) × 100%
偏差     = 实际进度 − 时间进度
```

| 偏差 | 判定 | 预警 |
|---|---|---|
| ≤ −25% | 严重滞后 | AL-02 红 |
| < −10% | 滞后 | AL-01 橙 |
| > 0 | 超前 | — |

**汇总口径**（`aggregation_service._weighted`）：
- 子项目 → 大项目：按权重加权；**未设权重按等权**
- 学院进度 = 该学院在该大项目内子项目加权
- 全校进度：按大项目等权（参数 `aggregate.school.mode=EQUAL`）
- 已结项子项目默认按 100% 计入（参数 `aggregate.include_closed`）

### 4.3 报表填报

**入口**：报表管理 → 报表填报

| 类型 | 周期 | 默认截止 | 字段 |
|---|---|---|---|
| 日报 | 当天 | 次日 00:00 | 今天做了什么 / 明天计划 / 问题 |
| 周报 | 周一~周日 | 次周一 12:00 | 本周进展 / 下周计划 / 问题风险 |
| 月报 | 自然月 | 次月第 3 个工作日 18:00 | 本月完成 / 下月计划 / 问题 / 建议 |

> 截止时间可在「参数配置」调整：`report.weekly.deadline_weekday/hour`、`report.monthly.deadline_workday/hour`。
> 日报默认关闭，开关为 `report.daily.enabled`。

**提交时的 5 条校验**（`report_service.submit`）：

1. 子项目必须存在且未删除
2. **数据范围校验**：只能给有权访问的子项目提交
3. 已结项子项目不能提交
4. **不能提交未来周期**
5. **超过「截止 + 补填期」不再接收**（补填期 = `report.correct_days`，默认 3 天）

**便捷功能**：
- 周报可点「生成周报初稿」，自动拼装本期进度记录，改几个字即可提交
- 同周期重复提交视为**更正**（`correct_count` +1）
- 3 天内可自行更正；超 3 天需权限

**作废**：仅 `report:void`（项目总负责人/管理员），必须填理由，作废后该期重算为「缺交」。

### 4.4 预警引擎（11 条规则，自动跑）

| 编号 | 类型 | 触发条件 | 等级 | 可手工关闭 |
|---|---|---|---|---|
| AL-01 | 进度滞后 | 偏差 < −10% 且持续 3 个有效日 | 橙 | ✅ |
| AL-02 | 严重滞后 | 偏差 ≤ −25% | 红 | ✅ |
| AL-03 | 进度停滞 | 超过 21 个有效日未更新 | 橙 | ✅ |
| AL-04 | 进度回调 | 本次进度低于上次 | 黄 | ✅ |
| AL-05 | 项目临期 | 距结束 < 30 天且进度 < 80% | 红 | ✅ |
| AL-06 | 报表逾期 | 补填期结束后仍未提交 | 黄 | ✅ |
| AL-07 | 连续未填 | 连续 3 个周期未提交 | 橙 | ✅ |
| AL-08 | 风险超期 | 风险超过计划闭环日 | 橙 | ✅ |
| AL-09 | 责任空缺 | 学院或子项目无负责人 | 红 | ❌ 只能补数据自动关 |
| AL-10 | 计划缺失 | 子项目无计划起止 | 红 | ❌ 只能补数据自动关 |
| AL-11 | 长期零进度 | 60 个有效日零进度 | 橙 | ✅ |

**降噪设计**：
- **7 天内同源去重**，重复只累加 `merged_count`，不重复推送
- **折叠聚合**：按「大项目 → 学院」折叠展示
- 按角色过滤，各看各的
- 每日 08:30 汇总摘要（不是每条都发），只有红色实时推
- 状态为「处理中」的不再催

**处置流程**：
```
PENDING（待处置）→ CLAIMED（认领）→ CLOSED（关闭，填理由）
                         ↓
                    IGNORED（忽略，必须填理由）
                         ↓
                    TRANSFER（转交他人）
```
- 认领需 `alert:claim`，关闭需 `alert:close`，转交需 `alert:transfer`
- 超过处置时限（红 3 天 / 橙 7 天，参数可调）自动**升级**并通知上级
- 接收人兜底链：子项目负责人 → 学院负责人 → 大项目负责人 → 系统管理员

### 4.5 风险登记

- 登记：描述、等级（高/中/低）、负责人、计划闭环日
- 闭环：填实际闭环日期
- 超期未闭环触发 AL-08

### 4.6 定时任务时刻表

| 时间 | 任务 | 说明 |
|---|---|---|
| 每日 01:00 | 快照 + 扫描 | 生成进度快照，跑 11 条预警规则 |
| 每 30 分钟 | 超时升级 | 超过处置时限的预警升级 |
| 每小时 :05 | 增量扫描 | 补扫 |
| 每日 08:30 | 汇总摘要 | 参数 `notify.digest.hour/minute` |
| 每日 02:00 | 数据库备份 | 参数 `backup.hour/minute` |

> 快照用于画进度曲线：实际进度 vs 应到进度，两条线一交叉就看出从哪天开始慢了。

## 阶段 ⑤ 复盘与结项

### 执行步骤

1. **看板复盘**：进度总表（默认按偏差排序，最滞前在最上）、学院对比、预警统计、及时率
2. **子项目结项**：进度必须 **100%** 才能转 CLOSED
3. **大项目结项**：状态转 CLOSED
4. **导出材料**：项目台账 / 进度报表 / 报表材料（Excel 或 PDF，导出记审计）

### 状态机（子项目）

```
NOT_STARTED ──► IN_PROGRESS ──► CLOSED（需 100%）
     │               │
     └──► ABORTED ◄──┘
            │
            └──► IN_PROGRESS（重启）
```

- `CLOSED` 是终态，不能再变
- 已结项子项目**不能删除**
- 已结项子项目不再要求提交报表

## 附一、双日历口径（这是最容易做错的地方）

| 用途 | 口径 | 原因 |
|---|---|---|
| 时间进度 | **自然日** | 按日历天数推进 |
| 预警计时（停滞、滞后持续、零进度） | **有效日**（排除免填期） | 否则寒暑假会把预警全部误判 |
| 报表应填判定 | 有效日 | 免填期不要求填报 |

## 附二、上线执行顺序（给实施人员）

```
第 1 周  服务器部署 + 建管理员账号
第 2 周  录学院 → 导人员 → 配角色授权 → 调参数 → 设免填日历
第 3 周  建 1 个试点大项目：配参与学院 → 建子项目 → 完整性检查通过
第 4 周  试点学院实跑一个周期：填进度 + 交周报 + 处理预警
第 5 周  看试点数据，校准预警阈值
第 6 周  全校推广
```

**R 类前置条件**（缺了会卡住）：

| 编号 | 需要学校提供 | 找谁 | 什么时候 |
|---|---|---|---|
| R1 | 统一身份认证对接资料 | 信息化部门 | 开发启动前 2 周 |
| R2 | 二级学院列表、教职工工号和所属学院 | 人事/信息化 | 开发中期 |
| R3 | 服务器、域名、HTTPS 证书 | 信息化部门 | 部署前 1 周 |
| R4 | 在建大项目清单、参与学院、子项目划分 | 产教融合归口部门 | 试点前 2 周 |
| R5 | 校历与作息 | 教务处 | 试点前 2 周 |
